# Техническое задание: редизайн окна AI‑ассистента

## Цели
- Повысить понятность, скорость выполнения задач и визуальную привлекательность окна AI‑ассистента.
- Достичь целевых метрик: CLS < 0.1, LCP < 2.5s, удовлетворённость ≥ 4.5/5, WCAG 2.1 AA.

## Область работ
- Полный UX‑аудит текущего интерфейса ассистента, подготовка отчёта.
- Проработка трёх концептов (Material, Neumorphism, Glassmorphism).
- Адаптивность 320 px – 4К, dark/light темы, accessibility, производительность, Figma‑макеты, прототип, A/B‑тесты, style guide и компонентная библиотека.

## 1) UX‑аудит (deliverable: PDF/Confluence)
- Пользовательские сценарии: старт диалога, быстрые действия, ввод, отправка, просмотр истории, вызов рекомендаций, копирование/экспорт.
- Диагностика проблем:
  - Недостаточные affordances у быстрых кнопок.
  - Слабая иерархия заголовков и вторичного текста, перегруз whitespace/пустоты.
  - Неочевидный статус (Online/Offline) и контекст проекта.
  - Поле ввода недостаточно контрастно и теряет фокус при скролле.
  - «Действия» и «История» смешаны, отсутствует понятная IA (информационная архитектура).
  - Tooltip'ы и микростейты не согласованы (hover/focus/disabled/loading).
  - Недостаточная клавиатурная навигация и ARIA‑семантика.
- Рекомендации: переработать IA, расставить приоритеты контента, усилить явные маркеры состояния, добавить skeleton/empty‑states и обучающие подсказки.

## 2) Три концепта UI (deliverable: Figma frames)
- Material Design (чистый, системный):
  - Elevation для чата, четкая сетка, понятные поля ввода, яркие primary/secondary.
  - FAB для быстрых действий; статус/контекст в AppBar; карточки ответов с метаданными.
- Neumorphism (мягкий пластик):
  - Скруглённые контейнеры, subtle inner/outer shadows; пастельные цвета; минималистичные иконки.
  - Фокус‑контуры и контраст повышаем осознанно, чтобы сохранить AA.
- Glassmorphism (современный стекло):
  - Прозрачные панели, blur, тонкие «неоновые» акценты; микроанимации появления/печати.
  - Внутренняя сетка (12‑кол) и модульные секции: заголовок, статус, быстрые действия, лента диалога, поле ввода, боковая панель рекомендаций.

## 3) Адаптивность (deliverable: responsive specs)
- Брэйкпоинты: 320, 375, 414, 768, 1024, 1280, 1920, 2560, 3840.
- Правила:
  - 320–414: одно окно, полный скролл, sticky поле ввода; скрывать второстепенное.
  - ≥768: двуколоночная компоновка (диалог + панель рекомендаций/истории).
  - ≥1280: три области: диалог, рекомендации, операции/экспорт.
- Горизонтальный скролл запрещён; вертикальный — управляемый; максимум высоты 92vh для области диалога.

## 4) Темизация (deliverable: theme switcher)
- Тёмная/светлая тема, instant toggle.
- Design tokens: colors, elevation, spacing, radii, shadows, typography, motion.
- Контрасты:
  - Текст/фоны: ≥ 4.5:1.
  - Иконки/границы: ≥ 3:1 (в тёмной теме — повышенный контраст).

## 5) Accessibility (WCAG 2.1 AA)
- Клавиатура:
  - Полная навигация: Tab/Shift+Tab, Enter/Space для акций, Esc закрытие.
  - Focus trap в модальном режиме; видимые focus outlines.
- ARIA:
  - role="dialog", aria‑label для секций, aria‑live для ответа ассистента (polite).
  - Правильный порядок чтения; landmarks: header, main, complementary.
- Screen Readers:
  - Озвучивание статуса (Online/Offline), прогресса генерации (busy), ошибок.
- Цвет/контраст:
  - Проверки на AA; альтернативные индикаторы (иконки/узоры) для цветовой слепоты.

## 6) Производительность (perf budget)
- Цели: CLS < 0.1, LCP < 2.5s на 4G/мобайл; TTI < 3.5s; интеракции < 100ms.
- Меры:
  - Ленивая загрузка тяжёлых панелей (история/рекомендации).
  - Виртуализация списка сообщений (windowing).
  - Предзагрузка шрифтов: Inter + JetBrains Mono (цифры, код/метрики).
  - Кэширование аватарок/иконок; минимизация blur/фильтров на мобиле.
  - Skeleton для ответа и команд; приоритет загрузки поля ввода.

## 7) Figma deliverables (pixel‑perfect + tokens)
- 1 файл проекта с страницами:
  - Audit → Issues map
  - Concepts → Material/Neumorphism/Glassmorphism
  - Responsive → брэйкпоинты/сетки
  - Themes → dark/light
  - Components → ChatWindow, Message, QuickActions, StatusBadge, Toolbar, Input, Tooltip, Toast
  - Tokens → color/spacing/typography/elevation/motion (JSON exportable)
- Состояния: default/hover/focus/active/disabled/loading/error, пустые состояния, варианты с длинным текстом и код‑блоками.

## 8) Интерактивный прототип
- Click‑through + микроанимации:
  - Появление ответа (typing dots → fade‑in).
  - «Копировать» с вспышкой toast и лёгким glow.
  - Открытие «Рекомендации» с spring анимацией (малая дистанция, короткий duration).
- Характер анимаций:
  - Природные кривые: easeOut, spring (завышенная жёсткость на мобиле).
  - Длительность: 120–200 ms; без «тяжёлых» blur на low‑end.

## 9) A/B‑тестирование (≥ 4.5/5 удовлетворённость)
- Дизайн вариантов: A (Material), B (Glass) — переключатель по флагу.
- Метрики:
  - SUS и CSAT по опросам; Task Success Rate; Time To First Helpful Answer.
  - Клики по быстрым действиям; копирование; повторная активация ассистента.
  - Порог: средний балл ≥ 4.5/5, рост SUS ≥ +15% к базовой линии.
- План:
  - Выборка ≥ 200 пользователей; длительность 2–3 недели.
  - Логирование по варианту; отчёт с статистической значимостью.

## 10) Style Guide и компонентная библиотека
- Design system:
  - Типографика: Inter (UI), JetBrains Mono (числа/код).
  - Иконки: Lucide; сетка 8px; радиусы 10–14px; тени как токены.
  - Цвета: палитры для светлой/тёмной, повышенный контраст для critical/interactive.
- Компоненты:
  - ChatWindow, MessageBubble (user/assistant/system), QuickActionButton, StatusBadge, Toolbar, InputArea, Tooltip, Toast, Skeleton, ScrollArea.
  - Состояния и пропсы описать; таблица соответствия токенов → css vars.
- Handoff:
  - Figma specs, токены (JSON), экспорт иконок (SVG), карты состояний, motion‑guidelines.
  - Чек‑лист accessibility и performance.

## Информационная архитектура (IA)
- Header: заголовок + статус + переключатель темы.
- Main: диалоговая лента + быстрые действия.
- Complementary: рекомендации/история/операции (на ≥768px).
- Footer: поле ввода + вспомогательные кнопки (Attach, Copy, Send).

## Контентные и интеракционные требования
- Быстрые действия: до 4–6 кнопок, с чёткими глаголами («Анализ воронки», «Оптимизация бюджета»).
- Поле ввода:
  - Плейсхолдер‑подсказка; подсветка ошибок; счётчик символов (не навязчиво).
  - Горячие клавиши: Enter — отправка, Shift+Enter — новая строка, Ctrl/Cmd+K — команда.
- Сообщения:
  - Время/статус; копирование; «показать код/скрыть код»; разворачиваемые блоки.

## Технические ограничения и совместимость
- Подготовить макеты и компоненты так, чтобы их легко портировать на React + Tailwind + Radix/SHADCN.
- Учитывать существующие токены/vars; имена токенов в kebab‑case; экспорт в JSON.

## Приёмочные критерии
- Выполнены deliverables (аудит, 3 концепта, адаптивные макеты, темы, AA, перф, Figma + прототип, A/B план и отчёт, style guide, библиотека).
- Pixel‑perfect соответствие решённому варианту.
- Достижение CLS/LCP целей на демо‑сборке.
- Документация по токенам и компонентам готова для интеграции.

## Сроки и формат
- Неделя 1: UX‑аудит и концепты.
- Неделя 2: макеты адаптив + темы + tokens.
- Неделя 3: прототип + motion + accessibility.
- Неделя 4: A/B запуск + сбор метрик, отчёт + финальный style guide.
