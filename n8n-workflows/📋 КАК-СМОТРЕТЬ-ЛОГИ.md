# 📋 Как смотреть логи и ошибки в n8n

## 🔍 Где смотреть логи в n8n:

### 1️⃣ **Логи выполнения workflow:**

1. Открой workflow в n8n
2. Внизу экрана нажми **"Logs"** (или **"Логи"**)
3. Там будут все логи выполнения workflow
4. Можно фильтровать по статусу: Success, Error, Warning

### 2️⃣ **Логи конкретной ноды:**

1. Открой workflow
2. Кликни на нужную ноду (например, "💾 Save to Supabase")
3. В правой панели открой вкладку **"OUTPUT"**
4. Там будут данные, которые вернула нода
5. Если есть ошибка — она будет показана красным цветом

### 3️⃣ **Логи в Code нодах (console.log):**

1. Открой нужную Code ноду (например, "🔍 Обработать ответ")
2. В правой панели открой вкладку **"OUTPUT"**
3. Прокрути вниз — там будут все `console.log()` сообщения
4. Или нажми **"Logs"** внизу экрана и найди нужную ноду

### 4️⃣ **Логи выполнения (Execution Logs):**

1. После запуска workflow нажми **"Logs"** внизу
2. Выбери нужное выполнение из списка
3. Там будут все логи всех нод по порядку
4. Ошибки будут выделены красным

---

## 🐛 Как найти ошибку:

### Шаг 1: Запусти workflow

1. Нажми **"Execute Workflow"** (или **"Выполнить workflow"**)
2. Дождись завершения

### Шаг 2: Проверь статус выполнения

1. Внизу экрана будет статус: ✅ Success или ❌ Error
2. Если Error — кликни на него, чтобы увидеть детали

### Шаг 3: Проверь каждую ноду

1. Кликни на каждую ноду по порядку
2. Проверь вкладку **"OUTPUT"**:
   - Если пусто — нода не вернула данные
   - Если есть ошибка — она будет показана

### Шаг 4: Проверь логи Code нод

1. Открой Code ноды (например, "🔍 Обработать ответ")
2. В **"OUTPUT"** прокрути вниз
3. Там будут все `console.log()` сообщения

### ✅ Успешное выполнение:

```
   Is array: false

```

### ❌ Ошибка:

```
❌ ОШИБКА ОТ SUPABASE:
   Error: column "xyz" does not exist
   Details: Could not find the 'xyz' column
```

## 🔧 Частые проблемы:

### Проблема 1: "No output data returned"

**Решение:**
- Включи опцию **"Always Output Data"** в настройках ноды
- Или проверь, что предыдущая нода вернула данные

### Проблема 2: Пустой ответ от Supabase

**Решение:**
- Это нормально! Supabase при успешном UPSERT может вернуть пустой массив `[]` или пустой объект `{}`
- Проверь данные в Supabase SQL Editor:
  ```sql
  SELECT * FROM instagram_posts_stats ORDER BY updated_at DESC LIMIT 5;
  ```

### Проблема 3: Ошибка авторизации

**Решение:**
- Проверь API ключ в заголовках ноды
- Убедись, что используется `service_role` ключ (не `anon`)

### Проблема 4: Данные обрезаются

**Решение:**
- Используй `JSON.stringify($json)` вместо шаблонов `{{ $json.field }}`
- Проверь логи в ноде "📦 Подготовить для Supabase"

## 📝 Где искать конкретные логи:

### Логи получения постов:
- Нода: **"📸 Get IG Posts"**
- Вкладка: **"OUTPUT"**
- Или: **"Logs"** → найди ноду "📸 Get IG Posts"

### Логи обработки данных:
- Нода: **"🔄 Transform Posts"**
- Вкладка: **"OUTPUT"**
- Ищи: `📋 ПЕРВЫЙ ПОСТ (полностью)`

### Логи сохранения:
- Нода: **"💾 Save to Supabase"**
- Вкладка: **"OUTPUT"**
- Или: **"🔍 Обработать ответ"** → там будут логи обработки ответа

### Логи ошибок:
- Вкладка: **"Logs"** внизу экрана
- Фильтр: **"Error"**
- Или: красные сообщения в нодах

---

## ✅ Проверка успешного сохранения:

### В n8n:
1. Открой ноду **"🔍 Обработать ответ"**
2. Проверь OUTPUT — должно быть `"success": true`
3. Проверь логи — должно быть `✅ УСПЕШНО СОХРАНЕНО`

### В Supabase:
1. Открой Supabase → SQL Editor
2. Выполни:
   ```sql
   SELECT * FROM instagram_posts_stats 
   ORDER BY updated_at DESC 
   LIMIT 5;
   ```
3. Должны быть свежие записи

---

## 🆘 Если ничего не помогает:

1. **Проверь все ноды по порядку:**
   - Каждая нода должна иметь данные в OUTPUT
   - Если какая-то нода пустая — проблема в ней

2. **Проверь логи выполнения:**
   - Нажми **"Logs"** внизу
   - Найди последнее выполнение
   - Проверь каждую ноду

3. **Проверь данные в Supabase:**
   - Может быть данные сохраняются, но workflow не показывает это
   - Выполни SQL запрос для проверки
