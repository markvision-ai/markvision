# 📊 Где сохраняются "Новые подписчики" в Supabase

## ✅ Ответ

**Таблица**: `content_production_stats`  
**Столбец**: `followers` (INTEGER)  
**Workflow**: `INSTAGRAM-STATS-AGGREGATOR.json`

---

## 📋 Структура таблицы

```sql
CREATE TABLE public.content_production_stats (
  id UUID PRIMARY KEY,
  project_id UUID NOT NULL,
  period_start DATE NOT NULL,
  period_end DATE NOT NULL,
  publications INTEGER DEFAULT 0,
  stories INTEGER DEFAULT 0,
  reach INTEGER DEFAULT 0,
  comments INTEGER DEFAULT 0,
  followers INTEGER DEFAULT 0,  -- <-- ЭТО СТОЛБЕЦ "НОВЫЕ ПОДПИСЧИКИ"
  diagnostics INTEGER DEFAULT 0,
  sales INTEGER DEFAULT 0,
  revenue INTEGER DEFAULT 0,
  created_at TIMESTAMPTZ,
  updated_at TIMESTAMPTZ,
  UNIQUE(project_id, period_start, period_end)
);
```

---

## 🔄 Как данные попадают в таблицу

### 1. Workflow: `INSTAGRAM-STATS-AGGREGATOR.json`
- **Запуск**: Каждый день в 01:05
- **Нода "🧮 Рассчитать метрики"**:
  - Получает подписчиков из Instagram Insights API
  - Использует ноды:
    - "👥 Получить подписчиков" - текущее количество (`followers_count`)
    - "👥 Получить новых подписчиков" - новые за период (`followers_gained`)
  - Приоритет: если есть `followers_gained` за период, использует его, иначе `followers_count`
- **Нода "💾 Сохранить в Supabase"**:
  - Сохраняет в таблицу `content_production_stats`
  - URL: `https://pyscczcuersdjvpmkiec.supabase.co/rest/v1/content_production_stats?on_conflict=project_id,period_start,period_end`
  - Поле `followers` передается в `jsonBody`

### 2. Хук: `useContentProductionStats.ts`
- Читает данные из `content_production_stats`
- Используется в `useInstagramPlanFact.ts` для отображения в "План/Факт контент-производства"

## 🔍 Как проверить данные

### SQL запрос для Supabase SQL Editor:

```sql
-- Просмотр всех данных
SELECT 
    period_start,
    period_end,
    publications,
    reach,
    comments,
    followers,  -- <-- "НОВЫЕ ПОДПИСЧИКИ"
    diagnostics,
    sales,
    revenue,
    updated_at
FROM public.content_production_stats
WHERE project_id = '64c94e87-630c-470e-8ab1-8f7c8c835efa'
ORDER BY period_start DESC, period_end DESC;
```

### Проверка последних записей:

```sql
-- Последняя запись с подписчиками
SELECT 
    period_start,
    period_end,
    followers,
    publications,
    reach,
    comments,
    updated_at
FROM public.content_production_stats
WHERE project_id = '64c94e87-630c-470e-8ab1-8f7c8c835efa'
  AND period_start = '2026-01-01'
  AND period_end >= CURRENT_DATE - INTERVAL '2 days'
ORDER BY period_end DESC
LIMIT 1;
```

## ⚠️ Важно

1. **Период**: Данные сохраняются за период с 1 января по вчерашний день
2. **Обновление**: Каждый день в 01:05 workflow обновляет запись за весь период
3. **Приоритет**: Используется `followers_gained` (новые за период), если доступно, иначе `followers_count` (текущее количество)

---

## 🐛 Если данные не появляются

1. **Проверь workflow**: Убедись, что `INSTAGRAM-STATS-AGGREGATOR.json` активен и запускается
2. **Проверь логи n8n**: Посмотри логи ноды "🧮 Рассчитать метрики" и "💾 Сохранить в Supabase"
3. **Проверь Instagram API**: Убедись, что токен валидный и есть доступ к Insights API
4. **Проверь таблицу**: Выполни SQL запрос выше в Supabase SQL Editor
